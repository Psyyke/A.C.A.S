Hosting on localhost

  1. Install the A.C.A.S userscript.
  2. Select a webserver of your choosing, e.g. UwAmp.
  3. Create a folder named A.C.A.S to the root folder of your webserver. (e.g. www/A.C.A.S)
  4. Clone the repository and put the files inside the folder you just created.
  5. You should now see A.C.A.S running on http://localhost/A.C.A.S/.
  6. Make sure the A.C.A.S userscript is on and you should be good to go!

Make sure there are no additional folders which would make the URL like http://localhost/A.C.A.S/A.C.A.S/.

You can use GitHub Desktop to make Git actions such as cloning easy.

Production domain

The production site is https://acaschess.com/, with the app at /app/. Deploy the repository at the domain root, without the old project-folder prefix. Localhost keeps its /A.C.A.S/ folder.

  1. Configure acaschess.com as the custom domain with your hosting provider and finish its DNS and HTTPS setup. The root CNAME file supports GitHub Pages. Using Cloudflare for DNS does not require moving the site to Cloudflare Pages.
  2. Redirect www.acaschess.com to the HTTPS apex domain. When keeping an old-domain redirect, remove its /A.C.A.S prefix and preserve the remaining path and query string.
  3. Publish userscript version 2.6.0 or newer so installed scripts match the new domain. The updated script replaces saved legacy backend URLs while preserving localhost selections.
  4. Rebuild and publish the Calculation Server too. Older binaries do not allow the new website origin.

Browser storage belongs to its origin. Cached models and site-only preferences do not automatically move to the new domain. Userscript settings remain with the installed userscript, so update it rather than uninstalling it.

Keeping old links working

Keep the old GitHub Pages site published with assets/js/domain-redirect.js and the updated pages, including 404.html. The script only redirects the old host's /A.C.A.S URLs. It removes that prefix and keeps the remaining path, query string and anchor. It does nothing on the new domain or localhost.

For another page, add <script src="../assets/js/domain-redirect.js"></script> near the start of its head, before other scripts. Adjust the relative path for the page's folder depth. The 404 page loads the script from the old project root so missing deep URLs work too. The downloaded game collector keeps an inline copy to preserve its offline behavior and content security policy.

For search engines, a permanent HTTP 301 or 308 redirect is preferable when your old hosting supports it. JavaScript is a fallback, not a guarantee of unchanged rankings. Keep the new canonical URLs and sitemap.xml, and submit the new sitemap in Google Search Console. See Google's redirect guidance.

Seasonal effects

The home page has a little snowfall from December through February. To preview it any time, open the home page with ?snow. It stays off when your device asks for reduced motion. If the effect encounters an error, it disables itself and logs a console warning without interrupting the page.

A.C.A.S Userscript

Developing the userscript is easy, simply develop it as you'd any other userscripts.

Browsers might cache userscripts after you've refreshed the site enough times. If you notice your userscript being cached, disable the userscript, refresh the page, then enable the userscript and refresh the page again.
